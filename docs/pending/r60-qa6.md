## Decisions

- **Script Graph macro variable scope.** A macro's variable can be an **Outer** link
  (`Variable::outer`): its Get / Set nodes read and write the variable of the same name of the
  graph the macro is in (a macro inside a macro reaches the enclosing macro's, and through its
  links the graph's). Collapse To Macro links the variables the collapsed nodes used (it used to
  copy every graph variable into the macro, private to each use). A macro's own variables stay
  private per use (`macros_and_subgraph_assets_inline_with_their_own_state` unchanged); subgraph
  assets have no Outer variables (an error), and a link to a missing variable or one of another
  type is an error on the Subgraph node. The Blackboard shows the scope "Outer" inside macros.
  Why this over macro inputs/outputs: a Set inside the macro happens at its point in the flow,
  which outputs can't express, and linking keeps the collapsed nodes as they were.
  Old graphs collapsed before this keep their private copies (nothing tells a copy from a
  deliberate private variable). Tests: `visual_script::tests::macros_read_and_write_the_graphs_variables_through_outer_links`,
  `script_graph::tests::copy_paste_and_collapse_to_macro`.
- **Project lock.** The editor holds an operating-system lock on `Library/ProjectLock` while a
  project is open and writes its process id to `Library/ProjectLock.json`. A second editor
  (window or headless `--mcp`) finds the lock held: the project opens read-only at once
  (asset, scene, prefab, terrain, material, settings and meta saves through
  `asset_db::write_atomic` are refused; layouts aren't autosaved; the AI tools bridge doesn't
  start, so the first editor keeps its info file) and the window asks "Open Read-Only" or
  "Cancel" (back to the Hub). The lock belongs to the file handle, so a crash releases it and
  the next editor takes it over with no stale-pid guessing. Library caches stay writable.
  Tests: `project_lock::tests::*`, `asset_db::tests::read_only_projects_refuse_asset_saves`.

## Open (not fixed this round)

- LOD cross-fade only dithers lit opaque levels: Unlit, Fade/Transparent and `.shader`
  materials draw both levels whole inside the band (`draw_prep.rs` swaps only lit opaque draws
  to the Cutout pipeline). Needs unlit / blended dithered variants (a discard in the shared
  opaque entry points would cost early-Z everywhere) and a golden run.
- Parallel command encoding: no `on_uncaptured_error` handler, so a validation error in a
  part finished on a rayon worker aborts the process (the main-thread panic hook that flushes
  pending saves doesn't run). Before the split it panicked on the render thread.
- Material thumbnails count every background load as their own (`background_pending()`): during
  a long first import none is marked rendered and up to six are redrawn each frame.
- Directional lens flares use the raw light intensity, not the sun-height / moon one.
