## Memory investigation: no leak

Tools in `E:\MistyTargets\tmp\r68\tools`: `soak.py <minutes> <mode>` (modes full / play / open / rec / edit) drives an
editor built with a probe allocator (`alloc_probe.rs`: a counting global allocator with a
sampled heap profile, call stacks captured with `RtlCaptureStackBackTrace`; patched into
`main.rs` for the probe build only, never committed). `resolve.py` symbolizes the dumps offline
with dbghelp and the probe's PDB; `--diff` lists the stacks whose live bytes grew.

- **Play / Stop only** (Lumo's Leap stage 1, 78 cycles, 12 min): private bytes 908 → 925 MB,
  flat from cycle 5 (921); Rust heap 79 → 78 MB; handles 797 → 778; GPU 490 MB.
- **Full r67 cycle, 32 min** (171 cycles: stage 1 / Behaviour Tree demo / stage 2 opened in
  turn, an object added and undone, Play 6-9 s, a GIF every other cycle, autosave every minute;
  heap sampled every 256 KB, running beside a full test run): private bytes 935 (cycle 2) →
  1079 (cycle 20) → 1088 (cycle 123) → 1089 MB (cycle 171). The climb is a few steps of 25-56
  MB in the first 20 cycles (cycles 4, 6, 19), then flat: +10 MB over the last 150 cycles.
  Rust heap (every allocation, Lua included) 82-88 MB the whole time, no trend; the sampled
  profile at cycle 5 and at cycle 171 totals 82 MB both, and no call stack grew by more than one
  sample (256 KB). Handles 826 → 863 (flat from cycle 10), GPU memory 518-520 MB. Console: no
  warnings or errors.
- **Where the steps come from**: memory outside the Rust heap. wgpu's Vulkan backend
  (`gpu-allocator` 0.28) takes host-visible memory in blocks that grow with the number of
  blocks in use (staging for scene loads, the recorder's readback ring, per-frame uniform
  buffers) and frees an empty block unless it is the last one of its memory type; a block with
  one long-lived sub-allocation stays. That gives the step pattern and the plateau. Round 67's
  15 minutes ended inside the step phase.
- Checked and bounded on the way: the Console (ring buffer, capacity setting), recorder
  readbacks (dropped with the recording, 4 slots), Play sessions (scene snapshot and undo
  restored on Stop, `retire_ids_of` bounded by the edit scene's ids), the tile / sprite / shape
  caches (keyed by asset), autosave (backups removed on a clean exit: 9 files in the session
  folder at the end, removed by the exit).
- Nothing to fix.
- **Confirmation soak, 20 min** (same cycle, no heap sampling, beside the second full test run;
  108 cycles): private bytes 888 → 915 (cycle 5) → 937 (20) → 983 (40) → 1000 (80) → 1004 MB
  (100 and 108), the steps again early (cycles 25-35 and 70-80) and flat over the last 30
  cycles; Rust heap 79-85 MB with no trend; handles 783 → 837 (flat from cycle 40); GPU 490 →
  494 MB; no Console warnings or errors. The editor closed cleanly (no prompt) and its exit
  removed the 9 autosave backups.
