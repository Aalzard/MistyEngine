## Global project root audit

Every caller of `set_project_root` (52 sites):

- **Production**: the editor's `AssetDatabase::open` (one project per editor), the player's
  `Game::open_with` (one per process; its tests take turns already), the test-runner CLI
  (`testing::cli`, now a scoped root plus `set_project_root_if_unset`: in the engine's own suite
  `cli_writes_junit_xml_and_exit_codes` moved the global root to a temp project under every GPU
  test reading the sample through it).
- **Engine tests**: all set it to the repo's SampleProject (the same value), apart from the CLI
  test above. No race between them.
- **Editor tests in the full run** (2D platformer, tilemap, water, VFX portal and renders, VFX 2,
  UI showcase, shader graph demo and examples, the sample project's own tests, World Builder,
  MeadowDemo view lift): they now take `scoped_root` (this thread only) instead of moving the
  global root; the World Builder helper's set was redundant (`EditorState::new` sets it) and is
  gone; the MeadowDemo view-lift test's retry loop on `root_generation` is gone (with the counter).
- **Ignored generators / comparison renders** still set it on purpose (run alone).
- `test_sample::tests::tests_never_move_the_global_project_root` scans the editor's sources: a
  `set_project_root` outside `AssetDatabase::open`, its race tests and the ignored generators
  fails it.
